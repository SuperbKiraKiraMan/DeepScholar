# 工具接入与部署

## 1. MCP 的作用

MCP 是现有 Tool Registry 的外部适配层，不改变 Agent 主链：

```text
Planner / LLMWorker
-> ToolRegistry
-> MCPToolAdapter
-> MCPManager
-> stdio 或 Streamable HTTP Server
-> PaperSource-compatible ToolResult
```

FastAPI lifespan 启动时连接启用的 Server、完成 `initialize` 和 `tools/list`，再以 `mcp__server__tool` 名称动态注册；关闭时释放 Session 并注销工具。

## 2. 配置

复制示例配置：

```bash
cp mcp_servers.example.json mcp_servers.json
```

通过环境变量启用 MCP。配置文件只声明 Server、transport、命令和允许的工具；密钥放在 `.env`，不要写入 JSON、Trace 或错误信息。

单个 MCP Server 连接失败默认 fail-open：本地工具仍可使用，并在状态接口和 warning 中记录故障。

## 3. 安全边界

- 仅注册显式 allowlist 中的远端工具。
- 工具参数继续通过本地 JSON Schema 校验。
- 远端结果仍需转换成 `PaperSource`。
- MCP 返回的 metadata 不能绕过 Evidence 和 CitationCheck。
- stdio 子进程继承最小必要环境，不记录 API Key。

## 4. 本地启动

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload
```

浏览器访问 `http://127.0.0.1:8080`。运行前至少配置模型与搜索 Provider 所需的环境变量；离线测试可使用 `agent_mode=rule` 和 Mock Provider。

## 5. Docker

```bash
docker compose up --build
```

镜像使用非 root 用户运行 FastAPI 和可选的 stdio MCP 子进程，提供 `/health` 健康检查。Compose 把 `data/` 挂载为数据卷，以保留 SQLite 历史和本地索引。

容器内的 MCP command 必须存在于镜像；宿主机绝对路径不能直接在容器内使用。远程 MCP 需要容器网络可访问对应地址。

## 6. 部署边界

当前架构是单实例应用：活动 Run、SSE Queue 和取消状态位于进程内，SQLite 保存完成态。它适合本地演示和单用户部署，不是分布式高可用平台。

若扩展为生产服务，需要增加认证、外部任务队列、共享事件存储、PostgreSQL、数据库迁移、幂等任务和租户隔离。
