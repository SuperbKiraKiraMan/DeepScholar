# 本地论文数据与质量

## 1. 数据链路

本地论文能力复用既有 Retrieval 基础设施：

```text
Zotero / PDF
-> 文本解析与质量检查
-> Section-aware Chunker
-> BGE-M3 Embedding
-> Qdrant / SQLite 本地索引
-> LocalPaperSearchTool
-> Worker Observation
```

Agentic Retrieval 只把 `local_paper_search` 加入受控工具集合，没有重写解析、Embedding 或 VectorStore。

## 2. 文本质量

PDF 提取后先执行 Unicode 质量检查，识别替换字符、私用区字符、异常控制字符和连续乱码。严重乱码的文档不会静默进入新索引，以免“检索命中但证据不可读”。

Chunker 识别 References / Bibliography / 参考文献等章节信号，并把章节类型写入 metadata。参考文献列表适合发现论文关系，但通常不应作为正文论据。

## 3. 可追踪证据

本地 chunk 必须绑定稳定来源身份、论文标题和原始文件/URL 信息。EvidenceExtractTool 只从可追踪正文生成 EvidenceCard；CitationCheckTool 再检查 quote 是否确实存在于对应文本。

这使本地论文既能参与检索，也不会因为“文件在本地”就自动获得更高可信度。

## 4. 本地来源占比

系统不会强制保留固定的本地论文比例。策略是：

1. 对所有候选按主题相关性和质量排序。
2. 在相关性相近时优先保留有全文的本地来源。
3. 若本地没有相关论文，则完全使用外部来源。
4. 报告和来源列表显示真实 Provider，不伪造本地覆盖率。

固定 25% 配额会把无关论文带入证据链，因此不采用。

## 5. 安全迁移

索引升级使用新的 staging collection，验收通过前保留旧 collection，不原地覆盖。验证内容包括文档数量、metadata、中文质量、检索命中和 Evidence gate；确认无误后再切换配置。

本地模型与索引文件位于 `data/`，不应提交大型模型权重或包含个人论文内容的数据库。
